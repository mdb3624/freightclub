## CHG-863: US-848 Carrier Network Page — Rating Filter/Data Contradiction + Untracked Trust-Signal Debt

**Original Story:** US-848 (Carrier Network Page, Shipper persona, IN_PROGRESS, Jira FREIG-110)

**Discovered By:** BA persona, 2026-07-25, during a `/council-review` 48-hour test comparing BA-with-grounded-research against the BA output already shipped for US-848. Not a planned story — a requirements-quality gap found by re-deriving AC from carrier-vetting industry sources and diffing against the frozen story doc.

**Root Cause:**
1. **AC/BR contradiction, no research needed to catch it, just wasn't caught:** BR-3 requires a "minimum rating" search filter, but the Out of Scope section excludes "Carrier rating data (backend does not yet expose rating aggregates)." As written, the filter control has no data to filter against — either dead UI or an AC that will fail acceptance testing once implemented.
2. **Deferred fields are industry-standard carrier-vetting trust signals, not incidental gaps:** MC/DOT authority status, insurance-on-file verification, and FMCSA safety rating are the baseline signals every carrier-vetting source treats as load-bearing for any party evaluating a carrier (sources: [USA Truckload Shipping](https://usatruckloadshipping.com/carrier-vetting-process/), [CarrierCheck](https://carrierchk.com/blog/freight-broker-carrier-vetting-guide), [PFA Protects](https://pfaprotects.com/2025/04/10/how-to-vet-motor-carriers-to-ensure-success/)). US-848's Out of Scope silently defers "Carrier rating data," "Carrier bio / DOT number" as backend limitations with no companion tracking ticket — so this reads as a permanent scope cut rather than acknowledged, tracked debt.

**Blocker:** Neither item blocks US-848's current IN_PROGRESS AC-1–AC-8 (none of which depend on rating data) — this is a requirements-quality finding, not an implementation blocker.

**Options:**
1. Finish US-848 as-is (rating/DOT/insurance fields stay Out of Scope); track both findings here as CHG-863, fix the BR-3 wording, and open a follow-up story for trust signals once the backend exposes rating/DOT/insurance data.
2. Pause US-848 and rework AC now to remove the "minimum rating" filter entirely, deferring it correctly.
3. Block US-848 until backend rating/DOT/insurance aggregates ship, so the story can include trust signals from the start.

**Recommendation:** Option 1 — the contradiction is a one-line AC/BR fix (remove or correctly scope BR-3's "minimum rating" filter to match Out of Scope), and the trust-signal gap is real but backend-blocked; tracking it now prevents it from being silently lost when US-848 closes.

**Decision:** LIBRARIAN — finish US-848 as-is with CHG-863 tracked separately (Option A / Recommendation above). Follow-up story to be cataloged once backend rating/DOT/insurance aggregate endpoints exist.

**Status:** PARTIALLY RESOLVED — BR-3 wording fixed 2026-07-25 in `docs/business/stories/US-848_Carrier_Network_Page.md` (minimum-rating filter removed from BR-3, cross-referenced to Out of Scope with the backend-limitation reason). Still open: creation of the deferred-trust-signals follow-up story once backend rating/DOT/insurance aggregate endpoints exist.
