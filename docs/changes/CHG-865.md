## CHG-865: Consolidate Old-vs-New Package Entity Duplication (CarrierLane/CarrierEquipment/BlockedCarrier)

**Origin:** Follow-up from a session architecture-mapping pass that flagged duplicate class names across the legacy flat `com.freightclub.domain` package and the newer hexagonal `com.freightclub.modules.*.domain` packages: `CarrierLane`, `CarrierEquipment`, `BlockedCarrier`, `PayRateType`.

**What was found:** Investigation showed three distinct situations behind that flat list, not one uniform "duplication":

1. **`CarrierLane` / `CarrierEquipment`** — `domain.CarrierLane` and `domain.CarrierEquipment` were near-identical copies of `modules.carrier.domain.CarrierLane`/`CarrierEquipment` (old `CarrierEquipment` even already imported its enums — `EquipmentType`/`EquipmentCondition`/`EquipmentStatus` — from the new package). Exactly one class still imported the old versions: `LoadRecommendationService` (in `modules.recommendation.application`).
2. **`BlockedCarrier`** — not old-vs-new at all. `modules.shipper.domain.BlockedCarrier` is the real, fully-wired entity (`@Entity` mapped to `freightclub.blocked_carriers`, with its own Controller/Service/Repository). `modules.carrier.domain.BlockedCarrier` is a separate, structurally different domain model (has `blockedAt`/`unblockedAt` lifecycle, no `reason` field) with **zero consumers anywhere in the codebase** — dead code that was written but never wired to a repository, service, or controller.
3. **`PayRateType`** — `domain.PayRateType` is still imported by 5 legacy Load DTOs (`LoadResponse`, `CreateLoadRequest`, `UpdateLoadRequest`, `LoadFields`, `LoadSummaryResponse`); `modules.load.domain.PayRateType` is used by the new `LoadEntity`/`CreateLoadCommand`. This is a symptom of the much larger legacy-flat-Load vs. `modules/load`-hexagonal migration still in progress, not an isolated duplicate — consolidating it means rewriting the legacy Load controller/service/DTO stack that still backs the marketplace board today.

**Decision:** Fix (1) and (2) now — low risk, single-consumer or zero-consumer, verified safe by compile + targeted tests. Explicitly do **not** attempt (3) in this change — Load is the central aggregate and multiple write paths already have open cross-tenant-authorization debt (see `.claude/learnings.md` Technical Debt Ledger, HIGH item 2026-07-22/US-858); a rushed PayRateType consolidation risks silently touching that surface. Recommend an ARCHITECT-scoped follow-up story to decide the Load migration path rather than folding it into a debt-cleanup pass.
