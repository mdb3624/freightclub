## CHG-867: Renumber Orphaned CDN Story (FREIG-50 / old US-754) to US-867, Rescoped via Council Review

**Origin:** BA mandatory duplicate-capability check (`docs/roles/BUSINESS_ANALYST.md` step 2), triggered while drafting a new story for "should the frontend use a CDN" (raised 2026-09-01 via `/council-review`).

**What was found:**

1. **ID collision, story never cataloged:** `docs/business/stories/US-754.md` ("Optimize Cloud CDN Configuration for Asset Delivery," `DESIGN_APPROVED`, Jira FREIG-50, "To Do") existed as a story file and a Jira ticket, but was never given a row in `Story_Map.md`. That ID was independently reused there for an unrelated story ("Carrier Scorecard — Detailed Metrics," `MIGRATION_PENDING`, Phase 9, row 210) — which itself has no story file. Same failure mode as CHG-864 (2026-07-25): a story drafted off-cycle, never cataloged at ID-assignment time, later collided with unrelated work.

2. **Wider pattern, not fixed here (flagged only):** the same collision exists across the entire `US-751`–`US-757` range. Story files + Jira mapping document a performance-optimization backlog (Code-Split Auth Module, Lazy-Load Font Subsets, Replace Zod Validation, CDN Config, Replace React Query, Login Hydration, Trucker CPM Calculator — all Jira "To Do", FREIG-47–53). `Story_Map.md`'s Phase 9 "Admin & Intelligence Tools" section independently uses the same seven IDs for a completely different set of stories (Dispute Resolution Tools, Platform Health Metrics, Rate Benchmarking, ELD Integration, Document Upload, Freight Insurance, TMS API Access). **Out of scope for this CHG** — noted per `workflow.md`'s "flag debt outside current scope" rule. Needs its own audit/CHG pass before any of US-751–757 (either version) is picked up for design or implementation.

3. **Stale technical assumption:** FREIG-50's design assumed a GCP Load Balancer with Cloud CDN already (or soon to be) fronting Cloud Run. Current production architecture has no load balancer — nginx serves directly from Cloud Run. The story's AC/design section was written against infrastructure that doesn't exist.

**Decision:** Recover the CDN story, following the CHG-864 renumbering pattern:
- Old US-754 (FREIG-50) → **US-867** (FREIG-127)
- Content rewritten (not preserved verbatim, unlike CHG-864) to: (a) fix the stale GCP LB/Cloud CDN assumption, replacing it with the council-reviewed Cloudflare-free-tier-proxy approach; (b) reframe value around the Carrier/mobile-cellular persona specifically, per the council's Buyer/Expansionist/Futurist convergence, rather than a generic "platform operator" framing; (c) add an explicit AC excluding `/api/*` from any cache rule, closing a tenant-isolation risk the original story didn't address.
- FREIG-50 marked `[SUPERSEDED by FREIG-127]` in its summary, with a comment linking to the new ticket and explaining why.
