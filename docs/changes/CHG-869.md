## CHG-869: US-751 (Dispute Resolution Tools) — `Claim` Entity Does Not Cover Load Disputes

**Origin:** ARCHITECT Input Acceptance Gate check, flagged explicitly as a possible outcome in US-751's own story doc ("If `Claim` turns out not to cover load-level shipper/carrier disputes, ARCHITECT escalates via CHG per the Sequential Lock Protocol rather than this story being implemented against the wrong model").

**What was found:** `Claim` (`backend/src/main/java/com/freightclub/domain/Claim.java`) is the load-claiming mechanism — a Trucker claiming a load off the board (`ClaimStatus.ACTIVE`/`RELEASED`, `truckerId`, `claimedAt`/`releasedAt`). It has no concept of a Shipper or Carrier flagging a problem with a load, no reason/description field, and no resolution workflow. It is unrelated to the "dispute" concept US-751's business rules describe (BR-2: "shows the load, both parties, and the stated reason"; BR-3: forced-reason resolution).

**Decision (Option A — finish as-is, CHG tracked separately):** Add a small, dedicated `Dispute` entity/table rather than force-fitting `Claim`. This is additive, not a rework of US-751's business rules or ACs — the story's actual requirements (queue visibility, forced-reason resolution, audit trail, no payment logic) are unaffected; only the underlying data model changes from "reuse `Claim`" to "new `disputes` table."

**Actions taken:**
- [x] New `Dispute`/`DisputeStatus` domain model, `V20260901_1300__Create_Disputes_Table.sql` migration (tenant-scoped RLS, matching every other core table)
- [x] `DisputeResolutionService`/`DisputeController` implemented against the new model, gated `ROLE_ADMIN` (Super User) per US-751 BR-1
- [x] US-751 story doc's Background section left as-is (already anticipated this outcome); this CHG is the resolution record

**Not affected:** US-750, US-752, US-874-878 — none reference `Claim`.
